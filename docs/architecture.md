# 架构与协作

Codexbox 将 Main Agent 的决策和验收，与运行在 Ubuntu Machine 中的执行 Agent 分开。执行端运行 Codex CLI 和任务所需工具，可以通过客户端支持的远程连接使用独立会话。模型和认证由部署者选择与配置；不同客户端和供应商的能力、工具兼容性及费用需要分别评估。

## 职责

- Main Agent：理解需求，确定目标与授权边界，进行关键决策，验收结果并向用户交付。
- 执行 Agent：在约定范围内调查、实施和验证，返回结果、证据、实际变更和阻塞。
- 用户：提供目标、必要约束及涉及权限或不可逆操作的授权。

独立会话不意味着独立文件系统或权限。远程连接、会话创建、消息发送和模型调用是否可用，取决于客户端及其授权；连接成功也不代表写入、长任务和恢复均已验证。

## 任务契约

委派时提供目标及验收标准、必要上下文、执行范围、权限边界、阻塞时的处理方式和交付格式。不假定执行端继承了主会话上下文。任务完成后检查文件、命令结果及适用的运行状态，不仅依据 Agent 的总结。

适合委派的工作包括边界清晰、结果可独立验收的调查、编码和测试。需要共享文件或同一 Git 工作区时，避免并发修改同一文件、分支或索引；必要时使用独立工作区。发现结果不明时先核对实际状态，避免重复执行。

## 取舍

Linux 环境有助于维护独立工具链，但宿主共享带来便利的同时扩大了可访问范围。第三方模型可能改变成本和能力表现，实际工具调用、质量和数据处理方式需要逐项评估。跨设备访问及网络依赖也需要根据实际部署验证，不属于本项目默认提供的能力。
